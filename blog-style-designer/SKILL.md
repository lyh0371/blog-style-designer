# blog-style-designer · 个人博客风格设计师

唯一交付物：一份最终确认后的《UI 风格 MD 文档》。
中间产物：每步一个 HTML 对比预览页（供用户在面板中查看并选择）。
不写任何实际站点代码。

## 工作流总览（每轮 = 选择步 + 实现步）

```
第1步 风格选择（5选1）→ 第2步 风格实现（该风格3种做法选1）
  ↓
第3步 配色选择（5组选1）→ 第4步 配色实现（该配色3种应用选1）
  ↓
第5步 导航选择（3选1）→ 第6步 导航实现（该导航3种细化选1）
  ↓
第7步 高保真首页（3版不同诠释选1 → 可微调循环直到"确认"）
  ↓
沉淀《UI 风格 MD 文档》
```

- 每步生成 1 个 HTML 对比页，存到工作目录 `preview/` 下，按步编号命名：`preview/step1-styles.html`、`step2-style-impl.html`、`step3-colors.html`、`step4-color-impl.html`、`step5-layout.html`、`step6-nav-impl.html`、`step7-hifi.html`。
- 每步结束后用 present_files 打开该 HTML，并在回复中列出编号选项（如「回复 1-5 选择，或直接描述你的倾向」）。
- 用户确认后，把该步选择记录在对话上下文中（风格名与诠释、配色组、布局组合、实现编号），再进入下一步。

## 通用规则（每步都必须遵守）

1. **同一内容渲染所有选项**。所有候选方案必须渲染同一份虚构博客内容，保证横向对比公平：
   - 博客名：`慢速飞行`
   - 文章：`关于把博客重新写起来这件事`（2026.03.14）、`一期一会的读书笔记 · 三月`（2026.03.14）、`深夜代码与咖啡的化学作用`（2026.02.27）
   - 导航项：首页 / 文章 / 随笔 / 订阅
2. **对比页外壳统一**：页面自身用中性深色背景（如 `#1c1c22`），每个候选包在一个带阴影的圆角 frame 里，上方标注编号（A/B/C 或 1-5）、方案名、一句话描述。参考现有 `preview/preview-round1-styles.html` 的外壳结构。
3. **接受自由输入**：用户可以回复编号，也可以自由描述（如「B 的卡片 + A 的字距」「圆角别太大」）。自由描述时 AI 现场调整方案并重新渲染供确认。
4. **实现步必须有实质差异**：每步的 3 种实现必须在排版结构、色彩策略或装饰手法上有方向性区别（见「实现差异定义」），绝不是微调参数的同质选项。若用户对任何候选不满意，同样按此规则出 3 个新变体供选择，而不是直接微调。
5. **支持跳轮**：用户说「你帮我定」时，AI 直接选定并**说明选择理由**，继续下一步。
6. **支持回退**：用户说「回到第 X 步」时，保留已确认的其他步选择，重跑该步。
7. **实现步可跳过**：用户说「直接走」时跳过当前实现步，以已选方案继续。
8. **禁止 lorem ipsum**：一律使用逼真的中文占位内容。

## 第 1 步 · 风格选择

- 从 `references/styles.md` 读取 5 种风格定义，每种渲染成一个迷你版首页（含页眉导航、最新文章区、2-3 条文章卡、页脚）。
- 其中**风格 1「暖纸书卷风」必须与基准站 book.oiloil.org 保持一致**（配色、字体、书脊卡片等参数已在 styles.md 中实测提取，不得偏离）。
- HTML 页面标题：「博客风格候选」，副标题说明「五种风格渲染同一份内容 + 回复编号或自由描述」。

## 第 2 步 · 风格实现

- 用第 1 步选定的风格，渲染 **3 种不同实现**：同一风格 tokens，但排版结构、组件组织、装饰手法各有方向性差异（见「实现差异定义」）。
- **基准锁定风格的约束**：若第 1 步选中的是 styles.md 中标注「基准锁定」的风格（如风格 1 暖纸书卷，基准站 book.oiloil.org），3 种实现**必须在基准站的设计语言内**变化——只允许：浅色/深色模式、区块顺序与密度、封面配色方案这类同级变体；布局骨架（如书封卡片网格、分区标题行、导航形态）与关键辨识元素不得改动。渲染前若对基准站的实际形态没有把握，应先用浏览器打开基准站截图确认，不得凭想象发挥。
- 选定后，该实现作为后续所有步骤的基准诠释，记录其特征要点。

## 第 3 步 · 配色选择

- 基于已锁定的风格与实现，生成 **5 组配色方案**。每组包含：底色、墨色（主文字）、强调色、次级色/辅助色，外加一句气质描述（如「黄昏书房」「清晨电台」）。
- 同一风格同一实现渲染 5 种配色。
- 注意：若第 1 步选了风格 1（暖纸书卷），其中**一组必须是基准配色**（paper `#faf8f4` / ink `#262421` / 琥珀金 `#c8a24b`），作为「与基准站一致」的选项；其余 4 组在该风格骨架上做色彩气质变体。
- 用户可自由描述偏好（如「强调色想要蓝一点」），AI 现场调出新方案补进对比页。

## 第 4 步 · 配色实现

- 用选定配色渲染 **3 种色彩应用方式**：强调色的用量与分布策略不同（大面积色块 / 克制点缀 / 渐变运用等），版式结构保持基准实现不变（见「实现差异定义」）。

## 第 5 步 · 导航选择

只选**导航位置（3 种）**，渲染为当前风格+配色+实现下的不同导航形态，纵向完整小样：

- **顶部导航**：logo 居左 + 链接居右 + CTA
- **左侧边栏**：竖排导航固定左侧
- **极简顶部单行**：仅一行报名 + 极少裸链接
- **中下方悬浮导航**：底部居中悬浮胶囊 Dock（参考 mumingfang.com），内容区完全让位给正文

用户报编号（1-3）或自由描述。**首页版式不单独选择**——直接沿用第 2 步选定的风格实现所带版式（如基准书封卡片网格）。

## 第 6 步 · 导航实现

- 用选定的导航形态渲染 **3 种细化实现**：密度与节奏、导航元素的组织（如是否带 CTA/装饰）、与首页的衔接方式不同，风格与配色不变（见「实现差异定义」）。首页版式保持第 2 步锁定的基准实现不变。

## 第 7 步 · 高保真首页（3 版选 1）

- 用前面所有选择渲染 **3 版完整首页**，三版在细节诠释上互不相同（按「实现差异定义」），均包含：完整页眉、导航、首屏（博客名 + 一句 slogan 或最新文章）、文章列表区（至少 5 条真实感条目）、侧栏或页脚（视布局而定）、页脚。
- 桌面端渲染（假设 1200px 宽），内容用逼真的虚构数据（文章标题、日期、阅读时长、标签等），不得用占位乱数文字。
- 用户选定一版后可继续微调（如「标题再大一点」「列表加个封面缩略图」）→ 更新该版再确认，直到用户说「确认」。
- 用户确认后进入沉淀阶段。

## 沉淀 · 《UI 风格 MD 文档》

- 文件名：`blog-style-guide.md`（用户指定位置则从其指定，否则存当前工作目录）。
- 结构严格按 `references/style-guide-template.md`，包含三大部分：
  1. **视觉规范**：配色 tokens（含深色模式可选）、字体层级、间距体系、圆角与阴影规则、气质描述
  2. **组件规范**：导航栏、页眉、文章卡片/列表项、按钮、标签、页脚等——每个组件给出结构与样式要点，**以第 6、7 步最终选定的实现为准**
  3. **CSS Tokens**：`--blog-*` 命名的 CSS 变量代码块 + 3-5 个核心组件的可复用样式片段
- 文档要求：脱离本 Skill 后，任何 AI 或开发者只读这一份 MD 就能还原整套风格。
- 写完后用 present_files 交付，并附一句总结（风格名 + 三大特征）。

## 实现差异定义（第 2/4/6/7 步共用）

每个实现步的 3 个候选必须至少在以下维度中做出**方向性不同**的选择：

1. **排版结构**：模块的组织骨架不同（如居中对称 vs 左对齐错落 vs 网格切分）
2. **色彩策略**：强调色的用量与位置不同（大面积色块 / 克制点缀 / 渐变过渡 / 仅用于交互态）
3. **装饰手法**：纹理、边框、阴影、图形装饰的用法不同（满铺 / 局部点缀 / 完全无装饰）
4. **密度与节奏**：留白松紧、字号层级跨度、区块间奏不同（疏朗大气 / 紧凑高效 / 大小对比强烈）

禁止：只改字号、间距、圆角等参数的"同质候选"。每个候选配一句特征描述（如「A：对称庄重，强调色只出现在交互处」）。

例外：基准锁定的风格（见 styles.md）不受此条约束——其实现步的变体范围以「基准语言内」为准，保持一致性优先于差异性。

## 风格库

五种风格的完整定义见 `references/styles.md`。用户若要求替换/新增风格（如 Y2K、Neo-Brutalism），现场按同样的结构补写风格定义并更新 styles.md，再渲染对比。若用户对任何候选不满意（如「这个不太好看」），按「实现差异定义」出 3 个新变体供选择，选定后沉淀进 styles.md 并同步更新第 1 步对比页。
